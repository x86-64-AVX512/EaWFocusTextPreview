# Интеграция EaW Focus Text Preview 0.7.7F1

Приложение предоставляет два машиночитаемых способа проверки. Оба используют
тот же `FocusCanvas`, bitmap-шрифты, `xadvance`, переносы и координаты, что
видимый предпросмотр.

## 1. Консольный арбитр

`EaWFocusTextPreviewCLI.exe` работает автономно и не требует запущенного GUI.

Одиночная проверка:

```bat
EaWFocusTextPreviewCLI.exe check --description "Армия: +5% Attack" --pretty
```

Проверка JSON-файла:

```bat
EaWFocusTextPreviewCLI.exe check request.json --pretty
```

Пакетная проверка:

```bat
EaWFocusTextPreviewCLI.exe check batch.json -o result.json --pretty
```

Динамическая локализация по умолчанию выключена, поэтому папка мода для
обычных проверок не нужна. Для включения передайте
`--dynamic-localisation`. Тогда из мода загружаются `defined_text`, имена
стран, персонажей и другие конечные варианты, а CLI выводит предупреждение в
stderr о нестабильности и возможной повышенной нагрузке. Путь берётся из
`settings.json` рядом с обоими EXE; его можно один раз выбрать в GUI. Если
настройка отсутствует или недействительна, динамическая проверка завершается
кодом `2`. `--no-dynamic-localisation` принудительно выключает значение из
JSON. `--language` выбирает язык локализации (`russian` по умолчанию).

Для потоковой обработки добавьте `--jsonl`: каждая непустая входная строка
считается отдельным JSON-запросом, каждый ответ также занимает одну строку.
Вместо имени файла `-` означает stdin.

Коды завершения:

- `0` — все запросы проходят выбранную политику;
- `1` — запрос корректен, но хотя бы один текст не проходит;
- `2` — ошибка JSON, параметров, ресурсов или подключения.

## 2. API запущенного окна

Команда `send` обращается к уже запущенному приложению:

```bat
EaWFocusTextPreviewCLI.exe send request.json --pretty
```

Чтобы одновременно заполнить поля видимого редактора:

```bat
EaWFocusTextPreviewCLI.exe send request.json --show --pretty
```

`--launch` запускает GUI перед подключением. Обычная проверка через API не
меняет содержимое окна; это происходит только при `show: true` или `--show`.

Сторонняя программа может обращаться к именованному каналу напрямую:

```text
\\.\pipe\EaWFocusTextPreview.API.v1
```

Протокол двусторонний. Один кадр состоит из:

1. длины UTF-8 JSON в байтах — беззнаковое 32-битное число little-endian;
2. ровно указанного количества байт UTF-8 JSON.

На каждый запрос сервер возвращает один кадр того же формата. Максимальный
размер JSON — 8 МБ. Один клиент может последовательно отправить несколько
кадров. Старый односторонний канал плагина Notepad++ имеет другое имя и
остаётся совместимым.

## Запрос

```json
{
  "id": 17,
  "key": "VED_focus_desc",
  "title": "ПИОНЕРЫ",
  "description": "Армия: §Y+5%§! Attack",
  "effect": "Произойдёт событие.",
  "glyph_priority": "ru",
  "language": "russian",
  "policy": "visual",
  "dynamic_localisation": false,
  "show": false
}
```

Поля `title`, `description` и `effect` необязательны и по умолчанию пусты.
`glyph_priority` принимает `ru` или `en`. `id` и `key` без изменений
возвращаются в результате, чтобы сопоставлять пакетные ответы.
`dynamic_localisation` принимает `true` или `false` и по умолчанию равно
`false`. Папка мода обязательна только при `true`; функция экспериментальна,
нестабильна и может заметно повысить нагрузку. `language` выбирает язык
загруженного мода. При включении токены scripted localization вида
`[Root.NAME]`, а также конечные встроенные функции вроде
`[Root.GetName]`, `[Root.GetLeader]` и `[Root.Capital.GetName]` автоматически
заменяются вариантом, дающим худшую фактическую раскладку текста. Переменные
вида `[?variable]` остаются неразрешёнными.

Политики:

- `visual` — зелёный и жёлтый считаются допустимыми; красный не проходит;
- `strict` — проходит только зелёный, то есть формальный `maxHeight` также
  обязателен.

Пакет можно передать JSON-массивом либо объектом с `items`. Во втором варианте
верхнеуровневые `policy`, `glyph_priority`, `language` и
`dynamic_localisation` служат значениями по умолчанию:

```json
{
  "policy": "visual",
  "glyph_priority": "ru",
  "items": [
    {"key": "focus_a_desc", "description": "Короткий текст."},
    {"key": "focus_b_desc", "description": "Другой текст."}
  ]
}
```

## Ответ

Успешный одиночный ответ содержит `ok: true` и объект `result`. Основные поля:

- `status`: `green`, `yellow` или `red`;
- `fits`: итог выбранной политики;
- `fits_visual` и `fits_strict`: оба варианта решения одновременно;
- `description.lines`, `height_px`, `formal_overflow_px`,
  `panel_overlap_px`, `intersects_effect_panel`;
- `effect.lines`, `height_px`, `overflow_px`, `needs_scroll`;
- `title.lines`, `height_px`, `overflow_px`, `clipped`;
- `missing_glyphs`: список символов, отсутствующих в обоих атласах.
- `dynamic_localisation`: выбранные варианты, итоговый текст каждого поля и
  список неразрешённых токенов.

Для пакета возвращаются `results` и `summary` с количеством зелёных, жёлтых,
красных результатов, ошибок и элементов, не прошедших выбранную политику.
Ошибочный запрос содержит `ok: false` и `error.code`/`error.message`.
